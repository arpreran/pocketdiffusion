How PocketDiffusion works

A phone cannot afford Stable Diffusion's 102 UNet evaluations and 4 GB of FP32 weights. PocketDiffusion treats latency and memory as inputs: an adaptive planner chooses a distilled model, the number of steps, the native resolution, the decoder, the weight precision and the number of candidates; a custom denoising loop executes the plan with a deadline and an out-of-memory fallback chain; classical computer vision screens, corrects, upscales and verifies the result.

Deep learning

SD-Turbo (1 step) and SD1.5 + fused LCM-LoRA (2–8 steps), our own sampling loop, FP16, INT8/INT4 weight-only quantisation written from scratch, a 6-layer text encoder distilled from the 12-layer CLIP encoder, TAESD decoder, CLIP re-ranking, OWLv2 verification.

Classical computer vision

Guided filter (from scratch), shades-of-gray white balance, adaptive gamma, CLAHE, saturation soft-knee, FFT detection of 8-px decoder grids + notch filter, Iterative Back-Projection super-resolution, NIQE from scratch, HSV colour naming inside detected boxes.

Full stack

FastAPI backend with a single GPU worker and Server-Sent-Events streaming, SQLite (WAL) persistence for every generation, candidate, post-processing stage and denoising frame, and this framework-free frontend.
