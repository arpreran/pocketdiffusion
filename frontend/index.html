How PocketDiffusion works

A phone cannot afford Stable Diffusion's 102 UNet evaluations and 4 GB of FP32 weights. PocketDiffusion treats latency and memory as inputs: an adaptive planner chooses a distilled model, the number of steps, the native resolution, the decoder, the weight precision and the number of candidates; a custom denoising loop executes the plan with a deadline and an out-of-memory fallback chain; classical computer vision screens, corrects, upscales and verifies the result.

Deep learning

SD-Turbo (1 step) and SD1.5 + fused LCM-LoRA (2–8 steps), our own sampling loop, FP16, INT8/INT4 weight-only quantisation written from scratch, a 6-layer text encoder distilled from the 12-layer CLIP encoder, TAESD decoder, CLIP re-ranking, OWLv2 verification.

Classical computer vision

Guided filter (from scratch), shades-of-gray white balance, adaptive gamma, CLAHE, saturation soft-knee, FFT detection of 8-px decoder grids + notch filter, Iterative Back-Projection super-resolution, NIQE from scratch, HSV colour naming inside detected boxes.

Full stack

FastAPI backend with a single GPU worker and Server-Sent-Events streaming, SQLite (WAL) persistence for every generation, candidate, post-processing stage and denoising frame, and this framework-free frontend.

Explainability

Explain re-runs an image with the UNet's 16 cross-attention layers recorded and shows, for every prompt word, which pixels it shaped (DAAM-style heat maps), plus a map that colours each pixel by its dominant word.

Image-to-image editing

Upload a photo or pick a result, describe the change and set how much may change: the picture is encoded by the VAE, noised to that strength and redrawn by SD-Turbo in 1–4 steps (SDEdit). Low strength keeps the layout; high strength follows the prompt.

Live preview & object repair

With Live preview on, every pause in typing renders a 1-step SD-Turbo sketch (~0.1–0.25 s, not saved). After generation, if the selection detector cannot find a requested object, that word's cross-attention is boosted (×2 → ×4 → ×8) and the same seed is regenerated; the new image is kept only if it finds more objects without losing prompt alignment.

Energy & a smaller model

The Lab reports GPU energy per image from the NVML energy counter. BK-SDM-Tiny, a distilled SD1.5 UNet with 0.32B instead of 0.86B parameters, is an extra low-memory option for the planner and the model menu.

Runs in your browser, too

The On-device page loads SD-Turbo into the visitor's own browser and GPU with WebGPU (ONNX Runtime Web) — no server at all, so it works even when the team laptop is off. Our own CLIP tokenizer in JavaScript and an in-browser protobuf rewrite (weights moved to "external data", zero-copy) make the 1.6 GB UNet fit: ~1.6 s per image on a laptop RTX 4060.

Dream mode

24 one-step SD-Turbo frames (~0.1 s each) whose starting noise moves along a sphere between two seeds, or whose prompt embedding glides from one prompt to another — a smooth morphing animation in about 2 seconds, saved as a looping WebP.

Private by default

Each browser gets an anonymous id: the gallery shows only your own images and only you can favourite or delete them; share links still open any image. Requests are rate-limited per browser so one visitor cannot fill the GPU queue.

On your phone

Installable web app (manifest + service worker, works offline for the app shell and saved images), voice prompts through the Web Speech API, one-tap style presets and share links that always reach the live server.
